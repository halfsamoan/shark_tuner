# toauner 디자인 플레이북

이 문서는 이 저장소에서 UI를 설계·구현하는 에이전트(코덱스)를 위한 디자인 규범이다. `AGENTS.md`의 하위 규범이며, UI 코드를 작성·수정하기 전에 반드시 읽는다. 근거 자료: `docs/research/ux.md`(튜너 UX 리서치), `reports/device/`(실기기 스크린샷), 5개 렌즈 UX 리뷰 종합.

---

## 0. 디자이너의 사고방식

1. **화면은 읽히는 게 아니라 조작된다.** 튜너는 문서가 아니라 계기다 — 요약이 먼저, 상세는 뒤에. 주목이 필요한 상태는 숫자가 아니라 형태(색·모양·위치)로 먼저 읽혀야 한다.
2. **치료 강도를 먼저 판단한다.** 모든 화면에 같은 힘을 주지 않는다. 라이브 튜너 = 이 제품의 히어로(최대 투자). 설정·진단 = 실용적 마감(과잉 디자인 금지).
3. **기존 시스템을 존중한다.** 우선순위: 사용자의 명시적 결정 > 이 플레이북 > 개별 판단. 이미 정의된 토큰·상태 이름을 임의로 바꾸지 않는다.
4. **카피는 디자인 재료다.** 버튼은 일어날 일을 정확히 말하고("이 곡으로 튜닝"), 에러는 해결법을 말한다("너무 작아요 — 더 세게 튕겨주세요"). 사과·모호함 금지. 시스템 구조가 아니라 사용자의 언어로 명명한다(사용자는 '카탈로그'가 아니라 '곡'을 검색한다).
5. **구조는 정보다.** 번호·구분선·뱃지는 내용의 사실을 인코딩할 때만 쓴다. 장식용 번호 매기기 금지.

## 2. 디자인 언어: 리눅스 터미널 (확정)

**세계관**: CRT 포스퍼 콘솔. 흔한 "검정 배경 + 형광 초록"은 AI 생성 디자인의 클리셰다 — 이 클리셰를 피하는 방법은 색을 바꾸는 게 아니라 **세계관을 구체화하는 것**이다: 모노스페이스 타이포, 스테이터스라인, 박스 드로잉, 블록 커서, 프롬프트 모티프가 함께 있어야 라임이 "터미널의 포스퍼"로 읽힌다. 라임 혼자면 클리셰, 세계와 함께면 아이덴티티.

### 2.1 타이포그래피
- **데이터 역할** (숫자·음이름·Hz·cents·상태줄): **D2Coding** (OFL, 한글 지원 모노스페이스). 400/700만 존재하므로 강조는 색·크기로, 합성 볼드 금지. 반입 전 라이선스 원문 확인.
- **본문 역할** (설명·안내문): **Pretendard**. 400 본문 / 600 강조(진짜 weight, faux-bold 금지). 터미널감은 데이터 타이포가 책임진다 — 한글 프로즈에 D2Coding을 쓰면 고정 전각이라 스프레드시트로 읽힌다(금지).
- **장식 역할** (스플래시·완료 시트 헤드라인, 선택): Neo둥근모 Code. 본문 사용 금지.

**6단 스케일 — per-size 라인하이트·트래킹으로 optical size 흉내** (이 6단 밖의 크기 임의 생성 금지):

| 역할 | 크기 / LH / 트래킹 | 폰트 |
|---|---|---|
| Cents 히어로 | 96 / 1.0 / **-0.02em** / tabular / weight 한 단 얇게 | D2Coding |
| 타이틀 | 32 / 1.1 / 0 | Pretendard |
| 서브헤드 | 20 / 1.3 / 0 | Pretendard |
| 본문 | 16 / 1.5 / 0 | Pretendard 400 |
| 캡션 | 13 / 1.45 / 0 | Pretendard |
| 상태줄 | 11 / 1.2 / **+0.04em** (Latin uppercase만) | D2Coding |

- **핵심: 96pt와 11pt를 같은 트래킹으로 렌더하지 말 것.** 큰 쪽은 조이고(-0.02em), 작은 쪽은 푼다(+0.04em) — Apple Display/Text optical split 흉내. 균일 트래킹이 AI 티.
- **tabular figures 강제** — 숫자 바뀌는 모든 곳(D2Coding 자동). 96pt cents 히어로가 -9→-10에서 폭 점프(reflow)하면 실패.
- 라인하이트: 한글 Pretendard 1.5 vs 모노 1.2~1.3 (한글이 세로로 더 높이 쌓임).
- **장식 all-caps 폐기.** `OPEN STRINGS` → 한글 정상 케이스 `개방현`. all-caps는 실제 기계 토큰(`DROP C`, `E2`)일 때만 작게·드물게·+0.08em로 "획득". GNOME HIG 명시 금지("모든 글자 대문자화 금지")이자 한국어 우선 정책과도 충돌.

### 2.2 컬러 시스템 (다크 온리 — Apple/GNOME HIG + 성숙한 터미널 스킴 기반 재조정)

- **게이트: 대비는 눈이 아니라 계산으로.** 본문 4.5:1 / large·non-text 3:1. 하나의 "dim"을 읽는 텍스트와 눈금에 겸용하지 말 것 — 이 혼용이 생성 팔레트가 AA를 깨는 이유. `grid.tick`/`line.hairline`은 3:1 미만이지만 **정보 비운반 장식일 때만** 허용(니들·라벨·그린존이 실제 인코딩을 담당).
- **온도 커밋**: 라임·앰버·canvas 언더톤이 전부 warm(옐로우-그린), `info.teal`만 의도된 쿨 카운터포인트 — 우연이 아닌 의도로 읽히게.
- 스캔라인/글로우: 불투명도 ≤6%, 설정에서 off, cents 판독을 1ms라도 방해하면 제거. 쉬는 인광 텍스트에 blanket glow 금지 — bloom은 발광원(활성 엣지·lock flood)에만.

### 2.3 모션 문법
- 터미널은 튕기지 않는다: ease-out·bounce 금지, **linear 또는 steps() 120~160ms**.
- 커서 블링크 530ms steps(1). 락 그린 플러드는 0ms 점등 → 200ms 유지 → 150ms 페이드.
- 유일한 연속 모션 = 니들(EMA 표시값). `prefers-reduced-motion`/시스템 애니메이션 축소 시 블링크·플러드는 정적 상태로 대체.

### 2.4 크롬 문법
- 스테이터스라인(tmux 스타일 하단 스트립): 형식 유지, 내용은 사용자 언어 — `● 듣는 중 │ DROP C │ A4 440`
- 검색 필드: `~/곡찾기 $ ` 프롬프트 + 블링크 커서. Ctrl K는 하드웨어 키보드 감지 시에만.
- 카드 테두리: **1px 단일선** 박스드로잉(`─ │ ╭ ╮`), 모서리 각짐 0~4px. rounded-lg 남발 금지, `╔═╗ ╣╠` 이중선 금지(kitsch).
- 현 칩: `[E2]` → 완료 `[E2 ✓]` → 감지 중 블록 커서 점멸.
- 완료 시트: `✓ 6/6 strings in tune` 체크리스트 + 요약 2줄.

### 2.5 깊이·재질 (제네릭 그림자 금지 — 표면 휘도로)
흐린 box-shadow **전면 금지**(다크에서 그림자는 저열하게 읽힘). 카드를 배경에서 분리하는 4가지:
1. **표면 램프 휘도 단계**(§2.2) — 레이어가 앞으로 오면 그림자를 더하는 게 아니라 표면을 한 단 올린다.
2. **1px hairline** `line.hairline` + square corner(0~2px).
3. **1px inner top 하이라이트** `rgba(230,239,232,0.04)` — CRT 베젤/스캔 bloom 흉내.
4. **1px inner bottom 라인** `rgba(0,0,0,0.4)`.
허용되는 유일한 outer glow = lock flood 인광 bloom, ≤200ms, **쉴 때는 절대 없음**.

### 2.6 아이콘 (터미널 글리프 우선)
- 기본은 텍스트 글리프·박스드로잉: `▲ ▼ ♭ ♯ ✓ ● │ ↑ ─ ╭ ╮ ▁ ▂ █`. 아이콘폰트 우회.
- 진짜 아이콘 불가피 시 monoline: **24px 1.5px 단일 획, butt/square cap, rounded join 금지, 코너 ≤2px, optical center.** Material rounded-filled·SF Symbols·lucide·이모지 혼용 금지 — 한 손으로 깎은 획 시스템 하나만.

## 3. 정보 계층 설계법 (화면별 목표 상태)

- **라이브 튜너 (무스크롤 필수)**: ① 컨텍스트 스트립(곡/튜닝/오프셋) ② 캡션 `Eb2 · 6번 줄 · 자동 인식` ③ **히어로: 부호 cents + 방향 화살표 (96pt)** ④ 라벨드 미터(-50/0/+50, 그린 존) ⑤ 단일 안내 슬롯 ⑥ 하단 엄지 존 현 칩(완료 핍) ⑦ 상태줄 한 줄. |오차|>50c → 코스 모드(소수점 숨김, 큰 화살표, "반음 이상 높음 ▼").
- **곡 상세**: 첫 뷰포트에 곡명(검증✓)/튜닝+한글 부제/개방현(굵기 비례)/스티키 CTA. 카포·오프셋(한 줄 설명)·상세정보는 아래.
- **홈**: 검색(히어로) → 최근 → "바로 튜닝하기" 프리셋 칩 → 결과 리스트(예외값만) → 0건 복구.

## 4. 튜너 미터 = 데이터 시각화

미터는 장식이 아니라 차트다. 데이터 시각화 방법론을 그대로 적용한다:

1. **인코딩 우선순위: 위치 > 길이 > 색.** cents 오차의 1차 인코딩은 니들의 **위치**다. 색은 보조 인코딩이지 단독 인코딩이 될 수 없다.
2. **색 단독 금지 (이중 인코딩 의무)**: 샤프/플랫은 색(앰버)만으로 구분하면 색각이상 사용자에게 소실된다 — 반드시 방향 화살표(▲▼)·♭/♯ 글리프·니들 위치가 함께 말한다.
3. **상태색은 예약어**: `lock.flood`/`lock.hold`는 인튠 락에만. "시리즈 4번 색"처럼 재사용하는 순간 성공의 의미가 죽는다.
4. **눈금은 후퇴색**: 그리드·틱은 `grid.tick` 이하로 가라앉히고 데이터(니들·그린 존)만 도드라지게.
5. **범위 밖은 정직하게**: 니들이 ±50c를 넘으면 끝에 붙이지 말고 클램프 + 셰브론(`↑ 범위 밖`)으로 "이 계기의 범위를 벗어남"을 명시.
6. **히어로 숫자는 stat 타일 원칙**: cents 히어로는 값+단위+방향 3요소가 한 덩어리. 소수점은 표시하지 않는다(내부 0.1c 유지, 표시 정수).
7. **히트 타깃 > 마크**: 현 칩의 시각 크기(42dp)와 무관하게 탭 영역은 ≥48dp.

## 5. 컴포넌트 상태 설계 (상태 머신 → 피그마 variants → 위젯)

상태 이름은 세 곳(피그마/코드/테스트)에서 동일해야 한다. 임의 개명 금지.

| 컴포넌트 | 상태 |
|---|---|
| `NoteChip` | idle → active(auto\|manual) → hearingOther → settling → locked → done |
| `Meter` | waiting → coarse → fine → locked |
| `GuidanceSlot` | pluckPrompt \| direction \| wrongString \| tooQuiet \| noisy \| settling |
| `StatusLine` | listening \| warning \| dev |

전이 규칙(요약, 상세는 `docs/ui-plan.md` 알고리즘 절):
- coarse↔fine 히스테리시스: 진입 |c|>55, 이탈 |c|<45.
- 색 경계 ±1c 히스테리시스: 5/15c 경계에서 플리커 금지.
- 파인튜닝(|c|<15) 중 현 재할당 금지. hearingOther는 2연속 프레임부터.
- lock: 새 피킹 후 1초 안에 안정화 추정값이 ±2c를 한 번 통과하면 즉시 완료. 빠른 경로를 놓치면 포스트어택 중앙값 ±5c(초보 기본, 설정 ±1~15) 750ms 유지 → 플러드+체크+햅틱(더블탭 50/50/50ms) → 다음 미완료 현.

## 7. 마이크로카피 규칙 (한국어 우선)

## 11.5 생성형 AI 티 킬리스트 (절대 금지 마커)

"터미널"이라고 들으면 AI가 자동으로 뱉는 기본값들. **이 앱에서 아래를 하나라도 하면 "생성된 UI"로 즉시 읽힌다.** Apple/GNOME HIG + 성숙한 base16/Gruvbox/Nord/Tokyo Night 스킴 대조로 도출.

1. **단일 패널색** — 모든 표면에 `#101512` 하나. 카드가 배경에 녹아 사라짐. 생성 디자인 1위 마커. → elevation 램프(§2.2).
2. **풀채도 네온 포스퍼** — `#B8F34A`+`#33FF66`를 near-black 위 full-chroma로. 이 "해커 그린 온 블랙"이 정확히 AI 기본값. `#33FF66`은 채도·휘도 최대 + 블루-그린이라 halation(번짐). 진짜 P1/VT220 인광은 **따뜻한 옐로우-그린**. → de-tuned 포스퍼.
3. **순수 블랙 canvas** — 배경이 `#000`에 붙음. 성숙한 스킴은 전부 base를 블랙에서 띄움(Gruvbox #282828, Nord #2e3440). OLED-해커 클리셰 + 텍스트 smear.
4. **라임의 다의성** — 브랜드 라임과 인튠 그린이 같은 옐로우-그린 계열. 역할은 밝기 아니라 **hue**로 분리해야 함(`brand.phosphor` vs `lock.flood`).
5. **rounded-lg + drop-shadow + 그라디언트** — Tailwind 기본 실루엣. 터미널은 flat·hairline·0~2px 코너.
6. **전면 중앙정렬 + 사방 균등 패딩** — 터미널은 좌측 앵커·ragged-right·컬럼 그리드. 대칭 중앙정렬은 모노스페이스 컬럼 문법 파괴.
7. **균일 크기 카드 대시보드 그리드** — "동일 타일 bento"는 정보 위계를 뭉갬.
8. **장식용 all-caps + wide tracking** — GNOME HIG 명시 금지. 한글 우선 규칙과 충돌.
9. **전면 네온 glow / text-shadow bloom** — 쉬는 인광 텍스트에 blanket glow. 진짜 잔상은 미묘하고 발광원에만.
10. **이중선 박스드로잉** `╔═╗ ╣╠` — 진짜 TUI(btop, bat, lazygit)는 얇은 단일선 `─│╭╮`을 드물게. 장식 이중선은 kitsch.
11. **장식용 blinking 프롬프트/커서** — `user@host:~$`를 비인터랙티브 텍스트에. 실제 입력받는 필드에서만.
12. **아이콘폰트/이모지** — lucide, ✅🎸🔥, Material rounded-filled. 콘솔 픽션을 즉시 깨뜨림.
13. **한글 본문에 모노스페이스** — D2Coding 한글 문단은 코드 리스팅으로 읽힘. 본문은 Pretendard.
14. **본문 프로즈를 accent(라임)로 칠하기** — accent는 인터랙티브/활성 마크에만.
15. **이모지 성공 confetti / center 성공 연출** — 글리프(✓ ▲ ▼ ♭ ♯)로 대체.

## 11.6 "진짜 vs 가짜 터미널" — Keep / Kill

> 판정 규칙: **글리프가 진짜 터미널의 박스드로잉 세트에 없으면, 여기에도 없다.**

**KEEP (authentic)**: 1px 단일선 박스드로잉 `─ │ ╭ ╮`(코너 0~4px, 드물게·구조적으로) · 블록 커서 `▁ ▂ █`(입력 필드만, 530ms steps(1)) · 현 칩 `[E2]`→`[E2 ✓]` · tmux 상태 스트립 · warm green-black canvas(`#0B0F0A`) · 앰버(`#F2A93B`)를 의도된 warm 카운터포인트로 · 좌측 앵커 프롬프트(`~/곡찾기 $`)·ragged-right·ch 컬럼 그리드·tabular figures.

**KILL (fake/AI)**: `╔═╗ ╣╠` 이중선 프레임 · ASCII-art/figlet 배너 · 튜너 canvas 안 lucide/이모지/Material 아이콘 · 풀채도 `#33FF66`/`#B8F34A` **채움** + halation · 단일 패널색 `#101512` · rounded-lg+그림자+그라디언트 · 사방 균등 패딩+중앙정렬 · 균일 카드 대시보드 · 장식 all-caps · 쉬는 텍스트 전면 glow · 경쟁하는 여러 blink 속도 · 장식용 `user@host:~$` · 이모지 confetti · accent로 칠한 본문.
