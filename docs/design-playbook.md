# toauner 디자인 플레이북

이 문서는 이 저장소에서 UI를 설계·구현하는 에이전트(코덱스)를 위한 디자인 규범이다. `AGENTS.md`의 하위 규범이며, UI 코드를 작성·수정하기 전에 반드시 읽는다. 근거 자료: `docs/research/ux.md`(튜너 UX 리서치), `reports/device/`(실기기 스크린샷), 5개 렌즈 UX 리뷰 종합.

---

## 0. 디자이너의 사고방식

1. **화면은 읽히는 게 아니라 조작된다.** 튜너는 문서가 아니라 계기다 — 요약이 먼저, 상세는 뒤에. 주목이 필요한 상태는 숫자가 아니라 형태(색·모양·위치)로 먼저 읽혀야 한다.
2. **치료 강도를 먼저 판단한다.** 모든 화면에 같은 힘을 주지 않는다. 라이브 튜너 = 이 제품의 히어로(최대 투자). 설정·진단 = 실용적 마감(과잉 디자인 금지).
3. **기존 시스템을 존중한다.** 우선순위: 사용자의 명시적 결정 > 이 플레이북 > 개별 판단. 이미 정의된 토큰·상태 이름을 임의로 바꾸지 않는다.
4. **카피는 디자인 재료다.** 버튼은 일어날 일을 정확히 말하고("이 곡으로 튜닝"), 에러는 해결법을 말한다("너무 작아요 — 더 세게 튕겨주세요"). 사과·모호함 금지. 시스템 구조가 아니라 사용자의 언어로 명명한다(사용자는 '카탈로그'가 아니라 '곡'을 검색한다).
5. **구조는 정보다.** 번호·구분선·뱃지는 내용의 사실을 인코딩할 때만 쓴다. 장식용 번호 매기기 금지.

## 2. 디자인 언어: 리눅스 터미널 (확정)

**세계관**: CRT 포스퍼 콘솔. 흔한 "검정 배경 + 형광 초록"은 AI 생성 디자인의 클리셰다 — 이 클리셰를 피하는 방법은 색을 바꾸는 게 아니라 **세계관을 구체화하는 것**이다: 모노스페이스 타이포, 스테이터스라인, 박스 드로잉, 블록 커서, 프롬프트 모티프가 함께 있어야 라임이 "터미널의 포스퍼"로 읽힌다. 라임 혼자면 클리셰, 세계와 함께면 아이덴티티.

### 2.1 타이포그래피
- **데이터 역할** (숫자·음이름·Hz·cents·상태줄): **D2Coding** (OFL, 한글 지원 모노스페이스). 반입 전 라이선스 원문 확인.
- **본문 역할** (설명·안내문): **Pretendard**. 터미널감은 데이터 타이포가 책임진다 — 본문까지 모노로 하면 한글 가독성이 죽는다.
- **장식 역할** (스플래시·완료 시트 헤드라인, 선택): Neo둥근모 Code. 본문 사용 금지.
- 타입 스케일 고정: 96(히어로 cents) / 32(음이름 캡션) / 20(섹션) / 16(본문) / 13(보조) / 11(상태줄). 이 6단계 밖의 크기를 임의 생성하지 않는다.
- 숫자가 정렬되는 모든 곳에 tabular figures (모노스페이스면 자동 충족). cents 히어로가 -9→-10으로 바뀔 때 폭이 흔들리면 실패.
- 대문자 라벨(OPEN STRINGS 등)은 letter-spacing +0.08em. 단, 한국어 우선 정책에 따라 크롬 라벨 자체를 한국어로 교체하는 것이 원칙.

### 2.2 컬러 토큰 (다크 온리 — 의도된 단일 테마)
| 토큰 | 값 | 역할 | 규칙 |
|---|---|---|---|
| `bg.terminal` | #0A0E0C | 화면 배경 | 순수 #000 대신 녹색기 블랙 — "선택된 중립" |
| `bg.panel` | #101512 | 카드·패널 | |
| `phosphor.lime` | #B8F34A | 브랜드·CTA·활성 강조 | 로고, 주 버튼, 활성 칩까지만 |
| `phosphor.green` | #33FF66 | **인튠 락 전용** | 다른 어디에도 쓰지 않는다. 상태색은 예약어다 |
| `phosphor.amber` | #FFB000 | 경고·크게 벗어남 | |
| `phosphor.dim` | #5A6E5E | 보조 텍스트·비활성 | |
| `ink.primary` | #E6EFE8 | 본문 텍스트 | 텍스트는 항상 잉크 토큰 — 시리즈색(라임 등)으로 본문을 칠하지 않는다 |
- **대비는 계산으로 검증한다, 눈으로 판단하지 않는다**: 본문 4.5:1, 대형(24px+) 3:1, 비텍스트 UI 3:1 (WCAG AA). 각 토큰 쌍의 대비값을 계산해 이 문서에 주석으로 남긴다. `phosphor.dim`은 본문 크기에서 AA 미달 가능성이 높음 — 13px 이하 사용 금지 예상, 계산으로 확정할 것.
- 스캔라인/글로우: 불투명도 ≤6%, 설정에서 off 가능, cents 판독을 1ms라도 방해하면 제거.

### 2.3 모션 문법
- 터미널은 튕기지 않는다: ease-out·bounce 금지, **linear 또는 steps() 120~160ms**.
- 커서 블링크 530ms steps(1). 락 그린 플러드는 0ms 점등 → 200ms 유지 → 150ms 페이드.
- 유일한 연속 모션 = 니들(EMA 표시값). `prefers-reduced-motion`/시스템 애니메이션 축소 시 블링크·플러드는 정적 상태로 대체.

### 2.4 크롬 문법
- 스테이터스라인(tmux 스타일 하단 스트립): 형식 유지, 내용은 사용자 언어 — `● 듣는 중 │ DROP C │ A4 440`
- 검색 필드: `~/곡찾기 $ ` 프롬프트 + 블링크 커서. Ctrl K는 하드웨어 키보드 감지 시에만.
- 카드 테두리: 박스 드로잉 감성(1px 라인, 모서리 각짐 0~4px — rounded-lg 남발 금지).
- 현 칩: `[E2]` → 완료 `[E2 ✓]` → 감지 중 블록 커서 점멸.
- 완료 시트: `✓ 6/6 strings in tune` 체크리스트 + 요약 2줄.

## 3. 정보 계층 설계법 (화면별 목표 상태)

- **라이브 튜너 (무스크롤 필수)**: ① 컨텍스트 스트립(곡/튜닝/오프셋) ② 캡션 `Eb2 · 6번 줄 · 자동 인식` ③ **히어로: 부호 cents + 방향 화살표 (96pt)** ④ 라벨드 미터(-50/0/+50, 그린 존) ⑤ 단일 안내 슬롯 ⑥ 하단 엄지 존 현 칩(완료 핍) ⑦ 상태줄 한 줄. |오차|>50c → 코스 모드(소수점 숨김, 큰 화살표, "반음 이상 높음 ▼").
- **곡 상세**: 첫 뷰포트에 곡명(검증✓)/튜닝+한글 부제/개방현(굵기 비례)/스티키 CTA. 카포·오프셋(한 줄 설명)·상세정보는 아래.
- **홈**: 검색(히어로) → 최근 → "바로 튜닝하기" 프리셋 칩 → 결과 리스트(예외값만) → 0건 복구.

## 4. 튜너 미터 = 데이터 시각화

미터는 장식이 아니라 차트다. 데이터 시각화 방법론을 그대로 적용한다:

1. **인코딩 우선순위: 위치 > 길이 > 색.** cents 오차의 1차 인코딩은 니들의 **위치**다. 색은 보조 인코딩이지 단독 인코딩이 될 수 없다.
2. **색 단독 금지 (이중 인코딩 의무)**: 샤프/플랫은 색(앰버)만으로 구분하면 색각이상 사용자에게 소실된다 — 반드시 방향 화살표(▲▼)·♭/♯ 글리프·니들 위치가 함께 말한다.
3. **상태색은 예약어**: `phosphor.green`은 인튠 락에만. "시리즈 4번 색"처럼 재사용하는 순간 성공의 의미가 죽는다.
4. **눈금은 후퇴색**: 그리드·틱은 `phosphor.dim` 이하로 가라앉히고 데이터(니들·그린 존)만 도드라지게.
5. **범위 밖은 정직하게**: 니들이 ±50c를 넘으면 끝에 붙이지 말고 클램프 + 셰브론(`↑ 범위 밖`)으로 "이 계기의 범위를 벗어남"을 명시.
6. **히어로 숫자는 stat 타일 원칙**: cents 히어로는 값+단위+방향 3요소가 한 덩어리. 소수점은 표시하지 않는다(내부 0.1c 유지, 표시 정수).
7. **히트 타깃 > 마크**: 현 칩의 시각 크기(42dp)와 무관하게 탭 영역은 ≥48dp.

## 5. 컴포넌트 상태 설계 (상태 머신 → 피그마 variants → 위젯)

상태 이름은 세 곳(피그마/코드/테스트)에서 동일해야 한다. 임의 개명 금지.

| 컴포넌트 | 상태 |
|---|---|
| `NoteChip` | idle → active(auto\|manual) → hearingOther → settling → locked → done |
| `Meter` | waiting → coarse → fine → locked |
| `GuidanceSlot` | pluckPrompt \| direction \| wrongString \| tooQuiet \| noisy \| settling |
| `StatusLine` | listening \| warning \| dev |

전이 규칙(요약, 상세는 `docs/ui-plan.md` 알고리즘 절):
- coarse↔fine 히스테리시스: 진입 |c|>55, 이탈 |c|<45.
- 색 경계 ±1c 히스테리시스: 5/15c 경계에서 플리커 금지.
- 파인튜닝(|c|<15) 중 현 재할당 금지. hearingOther는 2연속 프레임부터.
- lock: 포스트어택 중앙값 ±5c(초보 기본, 설정 ±1~15) 750ms 유지 → 플러드+체크+햅틱(더블탭 50/50/50ms) → 다음 미완료 현.

## 6. 모바일 인체공학

- 조작 요소는 하단 1/3 엄지 존에: 현 칩 행, CTA. 정보는 위, 조작은 아래.
- 탭 타깃 ≥48dp, 인접 타깃 간 ≥8dp.
- 튜닝 중 화면 꺼짐 방지(wakelock), 세로 고정 우선(가로는 P2).
- 폰트 스케일 1.3x에서 전 화면 검증, 2.0x에서 라이브 튜너만이라도 생존(히어로만 스케일 캡 허용).

## 7. 마이크로카피 규칙 (한국어 우선)

- UI 크롬 전부 한국어. 영어는 음악 표기법만: 음이름(Eb2), 튜닝 고유명(Drop D — 한글 부제 병기 "반음 내림"), 단위(Hz, cents).
- 같은 사실을 한 줄에 두 언어로 반복 금지.
- 안내문은 신체 동작을 말한다: "가장 굵은 6번 줄(E)을 한 번 튕기고 울리게 두세요" (O) / "신호 대기" (X).
- 성공 어감 예약: '안정화됨'→'측정 안정'. "완료"류 단어는 락/전체 완료에만.
- 전문용어 첫 등장에 ⓘ 시트: cents·기준 피치·녹음 오프셋 — 핵심 문장은 "앱이 자동으로 계산해요, 따로 할 일 없음".

## 8. 접근성 기준 (릴리스 게이트)

- TalkBack: 튜너 상태를 초당 1회 스로틀 라이브 리전으로("6번 줄, E플랫2, 132센트 높음, 낮추세요"). 장식 눈금은 시맨틱 제외. 모든 칩·버튼 라벨링.
- 햅틱 채널: lock=더블탭 / flat=느린 펄스 / sharp=빠른 펄스 — 화면을 안 보고 튜닝 가능해야 함.
- 색각: §4-2 이중 인코딩으로 충족. 확인법: 스크린샷을 그레이스케일 변환해 방향·상태가 여전히 읽히면 통과.
- 대비: §2.2의 계산 검증. reduced-motion 대응: §2.3.

## 10. 구현 레시피 (요약 — 전체 의사코드는 docs/ui-plan.md)

1. 표시 스무딩: `displayCents = ema(raw, |err|>10c ? 0.6 : 0.3)` — DSP 값 재사용, 표시층에서만.
2. 미터 좌표: `x = clamp(c,−50,50)/50 × halfWidth`, CustomPainter + RepaintBoundary, 60fps 프로파일.
3. 방향 텍스트: `sign(c)` → 풀기/조이기 + 회전량 `|c| ÷ (plain 45 : wound 100)c/쿼터턴` → "약 N/4바퀴"(1/8~2).
4. CRT 이펙트: 정적 오버레이 먼저 → 셰이더 스캔라인은 실기기 60fps 통과 후에만.
5. 자동 진행: lock → 750ms 셀레브레이션 → 다음 미완료 현(6→1) → 완료 시트 + `findPlayableWith()`.
