# toauner 제품 로드맵

## 목표

고정밀 주파수·센트 측정, 초보자용 페그 방향 안내, 장력·게이지 추천, 튜닝 안정성 진단, 곡별 튜닝 라이브러리를 갖추고 **곡 검색 → 튜닝 확인 → 바로 정밀 튜닝**으로 이어지는 Android/iOS 기타 튜너를 만든다.

단순한 크로매틱 튜너가 아니라 "이 곡은 무슨 튜닝인가?"라는 시작점부터 해결하는 것이 제품의 핵심 차별점이다.

## 핵심 사용자 흐름

1. 곡명 또는 아티스트를 검색한다.
2. 곡의 튜닝, 카포, 기준 피치, 검증 상태를 확인한다.
3. `이 곡으로 튜닝`을 누른다.
4. 악기 구성과 현재 음을 바탕으로 현별 목표음을 안내받는다.
5. 정밀 튜닝을 완료한 뒤 같은 튜닝의 다른 곡을 발견한다.

곡 데이터가 아직 없는 경우에도 튜닝 프리셋/커스텀 튜닝에서 3번 이후의 흐름으로 진입할 수 있어야 한다.

## 범위가 재구성된 마일스톤

### M0 — 측정 기반과 워킹 스켈레톤

Flutter 모노레포, 두 교체 지점(`PitchDetector`, `AudioCapture`), 순수 Dart MPM, 합성 신호 테스트, Android 오디오 캡처, 크로매틱 바늘 UI를 만든다.

완료 조건:

- `docs/accuracy-spec.md`의 합성 신호 Gate S1을 통과한다.
- 실제 기타 WAV 기준 Gate G1을 측정할 수 있는 리포트 도구와 코퍼스 규약이 있다.
- 실제 Android 기기에서 픽킹부터 첫 유효 프레임까지 p95 150 ms 이하를 목표로 측정한다.
- DSP steady-state CPU가 중급 Android 기기 한 코어의 20% 이하인지 측정한다.

### M1 — 곡 검색에서 정밀 튜닝까지의 제품 수직 조각

견고한 현별 튜너와 곡 라이브러리의 최소 완성본을 함께 출시 가능한 흐름으로 만든다. 곡 라이브러리는 더 이상 M2의 부가 기능이 아니다.

범위:

- Standard, Drop D, Half-step, Drop C, D Standard, 대표 7/8현 프리셋과 커스텀 튜닝.
- 자동 현 인식, 히스테리시스, 인튠 잠금, A4 415~466 Hz.
- UNPROCESSED → VOICE_RECOGNITION 폴백, RMS sanity check, 실제 샘플레이트 검증.
- 출처와 검증 상태가 있는 20곡 이상 시드, SQLite/FTS5 검색.
- 곡 상세의 튜닝·카포·기준 피치·cents offset 표현.
- `이 곡으로 튜닝` 원탭과 `현재 튜닝으로 연주 가능한 곡` 탐색.

완료 조건:

- 비기타리스트 사용성 테스트에서 6현 전체 튜닝 중앙값 90초 이하.
- 곡 검색 → 튜닝 완료의 핵심 흐름을 오프라인에서 끝낼 수 있다.
- 모든 출시 곡은 사람 검증 완료 상태이며 탭/가사를 포함하지 않는다.
- 실기타 Gate G1과 라이브 기기 Gate D1 결과를 환경별로 따로 기록한다.

### M2A — 초보자 페그 방향 안내

헤드스톡 레이아웃, 좌/우 위치, 레프티 여부, 감김 방향을 데이터로 표현하고 곡선 화살표와 회전량 힌트를 제공한다. 예측과 반대로 음이 두 번 움직이면 방향 반전을 제안한다.

완료 조건:

- 페그 방향 진리표의 모든 셀을 유닛 테스트한다.
- 3+3, 6인라인, 레프티, 클래식 실물에서 화살표를 검증한다.
- 잘못된 방향 안내를 감지하면 자동 진행을 멈추고 복구 선택지를 준다.

### M2B — 장력·게이지 추천

plain 현의 물리 계산, 검증된 wound 현 단위중량 데이터, 현재 장력 감각 유지 프로파일, 세트 추천과 안전 가드레일을 제공한다.

완료 조건:

- 골든 테스트가 0.1 lbf 반올림 단위로 재현된다.
- 공개 제조사 계산 결과 20개 스팟체크와 3% 이내다.
- 단위중량 출처/버전과 추천 근거를 추적할 수 있다.

### M2C — 튜닝 안정성 진단

30초 체크 플로우에서 attack overshoot, settle time, drift, step jump를 수집하고 가능한 원인을 설명한다. 진단은 최소 3회 픽킹과 신호 품질 기준을 충족할 때만 제시한다.

완료 조건:

- 관측값과 원인 가설이 UI와 데이터 모델에서 분리된다.
- 합성 시나리오와 라벨된 실기타 세션으로 오진/미판정률을 측정한다.
- 근거가 약하면 단정 대신 `판단하기 어려움`으로 종료한다.

### M3 — 네이티브 최적화와 출시

필요한 경우에만 C++ FFI 코어를 추가하고 Dart 코어와 같은 코퍼스로 A/B 검증한다. 접근성, 배터리, 개인정보, 오류 수집, 라이선스 게이트를 마무리하고 Android를 먼저 출시한다. iOS는 같은 도메인/DSP 계약을 유지한 플랫폼 어댑터로 진행한다.

완료 조건:

- 네이티브/Dart 코퍼스 패리티 차이가 0.5 cents 미만이거나 더 정확한 구현을 선택한 근거가 있다.
- 30분 연속 사용 시 목표 기기 배터리 소모 8% 이하.
- 의존성에서 금지 라이선스가 발견되면 CI가 실패한다.
- Android 클로즈드 트랙 2주 동안 P0 결함이 없다.

## 데이터 원칙

- 곡 튜닝, 카포, 기준 피치 같은 사실만 저장하고 탭/가사/앨범 아트는 포함하지 않는다.
- 각 곡 레코드는 `source`, `checked_at`, `checked_by`, `confidence`를 가진다.
- 검색 노출과 출시 포함 여부는 분리한다. 미검증 데이터는 개발 빌드에서만 보인다.
- Songsterr 등 외부 서비스는 사람 검증의 보조 자료일 뿐 런타임 필수 서비스가 아니다.
