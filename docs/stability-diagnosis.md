# 튜닝 안정성 진단 계약

## 목적과 범위

안정성 검사는 튜닝 완료 직후 같은 줄을 반복 피킹해 피치가 어떻게 움직였는지 보여준다. v1은 의료·정비 진단처럼 원인을 확정하지 않는다. 화면과 데이터 모델 모두 `관측값`과 `가능한 원인`을 분리하며, 근거가 부족하면 `판단하기 어려움`으로 끝낸다.

## 입력 경로

- 라이브 튜너가 이미 연 `AudioCapture` 세션과 DSP isolate를 재사용한다. 별도 마이크 세션을 동시에 열지 않는다.
- Android에서는 기존 계약대로 `UNPROCESSED`를 우선하고 sanity check 실패 시 `VOICE_RECOGNITION`으로 폴백한다.
- PCM이나 개별 피킹 트랙을 저장하지 않는다. isolate가 전달하는 어택 시각, raw cents, raw clarity, RMS만 메모리에서 소비한다.
- UI 표시용 `EstimateStabilizer` 결과는 튜너 화면에 계속 사용하지만, 어택 오버슈트와 정착 시간은 안정화 전 raw 프레임으로 계산한다.

## 30초 검사 절차

1. 측정할 현 하나를 고른다. 엔진은 그 현을 수동 타깃으로 고정한다.
2. 같은 현을 중간 세기로 한 번 튕기고 약 3초간 울린다.
3. 어택부터 2.5초의 프레임을 한 트랙으로 묶는다.
4. 신뢰 가능한 피킹 3회부터 결과를 표시한다.
5. 같은 현 5회가 모이면 RMS 차이를 보정한 오버슈트 변동계수(CV)를 추가한다. v1의 재현성 확인선은 `CV <= 30%`다.

다른 현이 반복 감지되면 측정값으로 섞지 않고 사용자에게 해당 현 번호를 알린다. 신호가 약하거나 clarity/유효 프레임 비율을 통과하지 못한 피킹은 제외 횟수로만 남긴다.

## 관측값

- `attackOvershootCents`: 50–150 ms 어택 구간의 대표 피치와 후반 정상상태 피치의 차이. 저음에서 첫 유효 추정이 늦으면 첫 추정 이후 150 ms를 대체 구간으로 쓴다.
- `settleTime`: 정상상태 기준 ±3 cents 안에서 300 ms 이상 유지하기 시작한 시각.
- `steadyStateDriftCentsPerSecond`: 정착 이후 raw pitch의 선형 기울기.
- `interPluckDriftCents`: 이전 신뢰 피킹의 정상상태와 다음 피킹의 정상상태 차이.
- `normalizedOvershootCoefficientOfVariation`: 5회 피킹의 peak RMS를 중앙값 기준으로 보정한 오버슈트 CV.

기본 신뢰 조건은 clarity 0.9 이상, 유효 프레임 12개 이상, 유효 비율 70% 이상이다. 수치는 `PluckAnalyzerConfig`와 `StabilityClassifierConfig`에 모으고 UI에 매직 넘버로 복제하지 않는다.

## 가능한 원인 표현

- 큰 오버슈트와 긴 정착이 반복되면 `강한 피킹 또는 가벼운 현 장력 가능성`으로 표현한다.
- 피킹 간 정상상태가 일관되게 낮아지면 `새 현의 늘어남 가능성`으로 표현한다.
- 임계 패턴이 없으면 `뚜렷한 불안정이 관측되지 않음` 또는 `원인을 좁히기 어려움`으로 표현한다.
- 너트 마찰은 튜닝 조작 직후의 계단 이동을 명시적으로 수집한 세션에서만 평가한다. 현재 기본 3–5회 피킹 흐름은 일반적인 음 전환을 너트 마찰로 오인하지 않도록 이 플래그를 만들지 않는다.

## 검증 상태와 남은 실제 기기 게이트

합성 raw 트랙은 오버슈트·정착·드리프트 분리, 저음 지연, 약한 신호 거부, 3회 미만 미판정, 5회 RMS 정규화 재현성을 자동 테스트한다. 남은 실기기 게이트는 toauner 자체 PCM 경로에서 같은 현을 5회 중간 세기로 피킹해 다음을 기록하는 것이다.

- 원시 트랙과 화면 수치가 같은지
- 5회 정규화 오버슈트 CV가 30% 이내인지
- 강/약 피킹과 저튜닝에서 제외 사유가 사용자 행동과 일치하는지
- `UNPROCESSED`와 폴백 소스가 결과에 미치는 영향

이 실기기 세션을 통과하기 전에는 안정성 수치를 절대 원인 진단이나 정확도 홍보 근거로 사용하지 않는다.
